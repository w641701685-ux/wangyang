# 持续强化方法

## 识别本轮学习任务

把“训练”落实为更新创作规则、审美案例与校核方法。只在用户提供新素材或提出任务时执行，不承诺后台自主学习或模型参数训练。

- **样稿学习**：从用户自己的稿、明确认可的稿或已取得的参考资料提炼方法。
- **反馈校准**：对照初稿、用户反馈和改稿，找出为什么不合适、怎样修改才成立。
- **技能融合**：从用户指定的其他技能选取有用方法，说明它解决婚礼创作的哪个问题。

用户已给足素材时直接处理；只在缺失信息会改变判断时补问。无法取得整本手册时说明实际阅读范围，不用目录、摘要或旧记忆冒充全文。

## 完成一次学习循环

1. **读取现状**：保留本场已选母题、认可段落、当前风格与流程；读取现有规则和最相关案例。
2. **定位变化**：引用必要的短句或准确概述反馈，找出问题发生在立意、证据、递进、语言还是现场节奏。
3. **完成修改**：先解决作品的问题；有原稿就给对应改稿，只有学习资料就提炼可执行方法，不虚构用户认可的成稿。
4. **提炼规则**：采用“在什么条件下 → 采取什么动作 → 为什么 → 哪些情况不适用”的形式，每次优先增加1–3条高价值规则。
5. **换素材检验**：用不同职业、相处方式或现场要求的材料检查迁移，避免只会复刻原案例。记录结果为自检或独立试用，不当成用户认可。
6. **按权限保存**：用户明确要求“训练、强化、更新技能、记为长期规则”等时，执行现有技能的更新与验证流程。普通评价只作用于当前稿，长期性不明的判断保留为候选。

## 区分规则与案例

| 类型 | 判断依据 | 使用方式 |
| --- | --- | --- |
| 长期规则 | 用户明确要求长期采用，或已有已保存的明确规范 | 加入通用规则；遇本轮明确例外时按本轮要求执行 |
| 场景方法 | 在某类素材中成立，有清楚适用条件 | 写明条件，例如真实影像支持时才用影像切入 |
| 本场要求 | 只针对这一对新人、场地或环节 | 留在本场作品，不写成所有婚礼的固定偏好 |
| 待验证判断 | 只有模型推断，或用户只说“可以试试” | 标为候选；不得称为认可稿或稳定审美 |

“太长”不等于所有开场都须压到固定字数；“不深刻”不等于多加典故；“这场别煽情”不等于以后删掉所有情感表达。用户说“这个可以试试”通常授权试写，尚不构成定稿认可。

## 记录最小有效案例

把案例放进主文件直接引用的 `references/calibration-cases.md`，用下面的字段记录；信息不足就明确缺失，不补造。

- 来源与状态：用户明确反馈／已认可稿／参考资料／自拟待验证；注明实际日期或可定位材料。
- 素材条件：只留理解方法需要的事实，匿名化人物；省略电话、地址及无关家庭隐私。
- 问题：用户指出了什么；原稿未取得时写“原稿未保留”，不制造差稿。
- 调整与依据：怎样组织证据、递进或停顿；有真实前后稿才保留必要对照片段。
- 适用边界：何时有效、不能推到哪些场次。
- 检验状态：尚未试写／自检完成／独立试用／用户明确认可，分别记录。

合并重复案例和同义规则；新的明确要求与旧规则冲突时注明适用范围或替换依据，避免把相反要求并排堆积。以可复用的方法为主，避免把整份问卷和大量成稿塞进技能。

## 融合其他技能

先读取用户指定技能的真实内容，再提出少量能解决当前问题的方法。让技法服从真实故事、单一主技巧和可听懂的表达。例如导演方法可帮助安排情绪、动作与留白，不能据此虚构对白或把婚礼稿改成复杂电影剧情。

保留本技能作为流程主线；不整包复制其他技能，不执行与婚礼写作无关的脚本或安装命令。用户仅要求学习某项方法时，不据此修改或删除其他技能。

## 保存前验证与交付

检查主文件可识别、引用文件存在、认可状态有依据、新规则没有覆盖本场特例。对复杂变化按技能管理流程使用独立任务检验，输入只给所需素材，避免告知预期答案。

优先复查四类边界：相识与相爱不混淆；通俗与深度能兼顾；改短仍保留证据；动作未完成不提前宣布。另用一个新素材检查新规则的适用范围。

完成保存后，用简短语言说明“本次学到什么、以后在哪类任务使用、还有什么待验证”。只有检查了新任务，才说做过迁移验证；只有用户明确认可，才说审美已获认可。不要宣称一次训练后永远不会偏离。
